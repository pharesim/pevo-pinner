## PINNER-CONTENT-HASH-VERIFY-ON-PIN (archived 2026-05-21) — superseded by pinner-embedded-ipfs-node-via-boxo

Hash-verify task closed as superseded after architect review on 2026-05-21 verified empirically that the implemented approach is structurally non-functional for any real `ipfs add`-produced CID. Commit `28167cb6` wrapped `EmbeddedNode.Pin`'s `io.Copy` in a `TeeReader` to the multihash function declared by the CID, then byte-compared the hasher result to the CID's multihash digest. Public IPFS gateways return reassembled UnixFS file content for `GET /ipfs/<cid>` with default `Accept` — sha2-256 of that body does not equal the CID's multihash digest (which digests the dag-pb root block: a UnixFS-protobuf wrapper for small files, a list of links for files >256 KiB). The test fixture `cidForContent` synthesized CIDs as `cid.NewCidV0(mh.Sum(content, sha2-256))` — a shape the real ecosystem never produces — which is why the green tests masked the structural defect. Verified via curl + multihash compare on three CIDs (`QmPZ9g...` 1091 B dag-pb CIDv0, `QmTudJ...` 21 B dag-pb CIDv0, `bafkrei...` 109 B raw CIDv1): all three sha256(body) does not equal multihash.digest. PEvO's own upload path uses Kubo defaults (CIDv0/dag-pb, no raw-leaves, default chunker), so 100% of PEvO-uploaded papers fail the verify too. The structural fix is not "patch the verify" but "replace EmbeddedNode's HTTP-cache architecture with a real in-process IPFS node via `github.com/ipfs/boxo`" — the original design intent (pinner ships as a single Go binary that embeds the IPFS node, one file to run for third-party libraries helping share PEvO content). New task filed: `pinner-embedded-ipfs-node-via-boxo.md`. The HTTP-cache verification approach is reverted as part of the boxo rewrite; until reverted it is fail-open (rejects no real content because no real CID hashes match, so the gateway-loop falls through every gateway and the final `return lastErr` short-circuits the pin entirely — net effect is autopin is broken for any real CID since `28167cb6` landed, not a security regression vs the pre-`28167cb6` state but a functional regression that should be tested for in beta). Sibling tasks `pinner-cid-validation-on-autopin-path` and `pinner-response-size-cap-on-gateway-fetch` archive independently on their own merits.
